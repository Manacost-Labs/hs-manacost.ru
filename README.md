# hs-manacost.ru

Приватный репозиторий кода и серверной конфигурации основного сайта Manacost.

## Что хранится в Git

- активная тема `Newspaper_new`;
- собственные и доработанные плагины;
- обязательные MU-плагины;
- публичные служебные файлы из корня сайта;
- актуальные nginx-правила origin-сервера;
- зафиксированные версии WordPress и внешних плагинов;
- безопасный сценарий выкладки на тестовый и production-сайты.

## Что намеренно не хранится

- `wp-config.php`, `.env`, пароли, API-ключи, сертификаты и приватные ключи;
- база данных и персональные данные пользователей;
- `wp-content/uploads`, S3-объекты, кэши, логи и резервные копии;
- WordPress core и сторонние плагины из wordpress.org или коммерческих архивов.

Медиатека является данными, а не исходным кодом. Её резервирование и восстановление должны выполняться отдельно через Object Storage и резервные копии базы.

> Репозиторий должен оставаться приватным: он содержит коммерческую тему Newspaper и внутренний код Manacost.

## Серверы

| Назначение | Домен | Корень |
|---|---|---|
| Тестирование | `test.hs-manacost.ru` | `/var/www/koloda/data/www/test-hs-manacost-wordpress` |
| Production | `hs-manacost.ru` | `/var/www/koloda/data/www/hs-manacost.ru` |

Текущие версии и перечень внешних зависимостей находятся в [`config/site.json`](config/site.json) и [`config/plugins.json`](config/plugins.json).

## Обычный процесс изменений

1. Изменить код в этом репозитории, не в `/var/www`.
2. Запустить `make check`.
3. Посмотреть, что будет скопировано на тестовый сайт: `./ops/deploy.sh test`.
4. Применить изменения на тестовом сайте: `./ops/deploy.sh test --apply`.
5. Проверить интерфейс, публикацию, изображения, счётчик просмотров и очистку кэша.
6. После одобрения посмотреть production dry-run: `./ops/deploy.sh production`.
7. Применить: `./ops/deploy.sh production --apply --confirm-production`.

Перед применением сценарий делает локальную резервную копию изменяемых каталогов. Он не изменяет базу, загрузки, WordPress core и сторонние плагины.

## Первичное развёртывание

1. Установить WordPress версии из `config/site.json` и создать отдельный `wp-config.php` из `config/wp-config.example.php`.
2. Установить сторонние плагины по `config/plugins.json` из официальных или лицензированных источников.
3. Развернуть код этим репозиторием.
4. Восстановить базу и медиатеку отдельным защищённым процессом.
5. Установить nginx-конфигурацию из `ops/nginx`, адаптировав IP, сертификаты и PHP-FPM socket к серверу.
6. Проверить конфигурацию `nginx -t`, затем выполнить функциональную проверку сайта.
