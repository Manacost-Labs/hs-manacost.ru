# Карточки статей

В редакторе записи или страницы нажмите **Вставить статью**, выберите Manacost
или Koloda Hearthstone, категорию и поисковый запрос. Выберите один или несколько результатов,
проверьте предпросмотр и нажмите **Вставить карточки**. Кнопка **Ещё категории**
загружает следующую страницу категорий, если каталог не отдал все сразу.

По умолчанию обложка находится слева. Вариант **Большая обложка** размещает её
над заголовком. Оба варианта показывают дату публикации, скрывают адрес сайта
и открывают статью в новой вкладке. Фон карточки прозрачен. В Classic Editor
карточка появляется прямо в тексте; в блочном редакторе вставляется штатный
блок «Произвольный HTML» через публичный API редактора.

Для отмены вставки используется обычная отмена редактора. Карточку можно удалить
как обычный фрагмент текста. Название, дата и URL обложки фиксируются в момент
вставки; для обновления данных вставьте карточку заново. Файл обложки не копируется
и не изменяется. Если у статьи нет изображения, выводится нейтральное место под
обложку. При недоступности внешнего изображения текст и ссылка продолжают работать.

## Подборки и настройки

Можно выбрать до шести статей, в том числе из разных источников. Поиск, категории
и переход между страницами сохраняют подборку. В списке «Выбранные статьи» кнопки
«Выше», «Ниже» и «Убрать» меняют порядок и состав. Повторное нажатие на результат
снимает выбор. Вставляется вся подборка одной операцией отмены редактора; если
получить хотя бы одну карточку не удалось, частичная подборка не вставляется.

Доступны четыре варианта: компактные карточки, большие обложки, сетка статей
и список с миниатюрами. Настройки позволяют выбрать до двух или трёх колонок
сетки, размер изображения, отступы, скругление, показ даты и полную либо узкую
центрированную ширину. Сетка автоматически уменьшает число колонок на узком
экране. «Сбросить оформление» возвращает исходные настройки, сохраняя выбор.
Настройки применяются только к новой вставке; ранее опубликованные карточки
автоматически не меняются. Для другого оформления старый блок следует заменить
новой вставкой; отдельного редактирования существующего блока в диалоге нет.

«Недавно вставленные в этом редакторе» хранит до шести последних материалов
только в памяти открытой страницы. История и последние настройки сохраняются
между открытиями окна, но сбрасываются при перезагрузке редактора. Cookies,
localStorage, пользовательские метаданные и новые таблицы не используются.

Все варианты остаются обычным HTML. Сервер проверяет пресеты по закрытому списку,
заново получает публичные данные каждой статьи и не принимает CSS или HTML
от браузера. Параллельная подготовка ограничена шестью выбранными статьями;
обычные transport timeout/cache/cooldown продолжают действовать.

## Владение и границы

`wordpress/mu-plugins/hs-article-cards.php` — загрузчик отдельного MU-плагина.
`admin.php` и `dialog.php` владеют интерфейсом редактора; `catalog.php` — локальной
выборкой и нормализацией публичных данных; `remote.php` — ограниченным HTTP-клиентом;
`render.php` и `card.css` — разметкой и отображением. Родительская тема, сторонние
плагины и rollout `hs-editor-workspace` не изменяются.

Доступ проверяется по nonce `hs_article_cards` и `edit_post` для текущего документа
в `wp_ajax_hs_article_cards`. Сервер заново получает выбранную статью по ID:
клиент не передаёт произвольные HTML или URL для вставки. Локальный каталог исключает
черновики, private и password-protected записи. Koloda используется только через
публичный REST API; текст закрытых/платных статей не загружается.

Существующие карточки — обычный `post_content`, без отдельной таблицы, метаданных
или shortcode. Запросы к провайдеру выполняются только при выборе в редакторе.
Нет новых обработчиков сохранения, отключения autosave/revisions или очистки кэша.
Текущий WordPress остаётся источником локального каталога: staging не обращается
к production-базе. Вставка внутренних ссылок использует штатный `get_permalink`.

## Дизайн и проверка

Компонент использует проектную шкалу: заголовок 18 px (16 px на узком экране), дата
14 px, интервалы 8/12/16/24 px. Шрифт наследуется, внешние шрифты не загружаются.
Обложка резервирует соотношение сторон; длинные названия переносятся полностью.
Системные шрифты админки, native dialog, видимый focus и кнопки не менее 44 px.
Действующие `responsive-experience-contract.json` и `typography-layout-contract.json`
применяются без исключений. Макет согласован в чате: прозрачный фон, без домена,
с датой, компактный и большой варианты.

```sh
python3 -m unittest tests.test_article_cards -v
bash ops/integration/article-cards.sh
make check
make code-quality
make integration
make visual
```

Сценарий интеграции работает только в disposable loopback WordPress. Отчёты и
снимки размещаются в `.artifacts/article-cards/`; пароли тестовых ролей не выводятся
и не сохраняются в Git. Внешний HTTP заменяется на границе провайдера, но WordPress,
SQL, TinyMCE, AJAX-права, фильтры, сохранение, preview и публикация выполняются реально.
Проверяются длинные названия, отсутствие обложки, ошибка/пустой ответ, страницы
статей и категорий, keyboard/Escape, ширины 320–1440 px и 200% zoom.

Контракт внешнего сервиса: `config/integrations/article-cards.json`.
Транспорт сохраняет порядок параметров: текущий API Koloda не включает обложки,
если `_embed` находится перед `_fields`. Этот случай закреплён регрессионной
проверкой; staging-сценарий дополнительно проверяет наличие реальных обложек.
После staging deployment workflow `Admin performance staging` запускает
`tests/article-cards/staging.mjs` с защищёнными диагностическими учётными данными.
Сценарий проверяет оба живых каталога, поиск, категории, вставку, сохранение
синтетического черновика и frontend preview. Только собственный черновик с
уникальным маркером перемещается в корзину; опубликованные материалы не меняются.
Отчёт `article-cards-staging` должен содержать `ok: true` перед promotion.
Отключение только внешнего каталога: `HS_ARTICLE_CARDS_KOLODA_ENABLED=false`
в управляемой runtime-конфигурации; секреты для этой интеграции не нужны.
Откат — revert точного релизного commit через staging/production pipeline.
Уже вставленные карточки останутся обычными ссылками с изображением и текстом.

## Известное ограничение соседнего редакторского плагина

В изолированном WordPress блочная вставка, сохранение и повторное открытие карточки
проверены. При этом `hs-api-gallery/editor.js` версии 1.0.4 вызывает ошибку
`Cannot set properties of null (setting 'onclick')` на экране Gutenberg.
Сравнение того же экрана с полностью отключённым UI карточек воспроизводит ту же
ошибку в том же файле. Новый плагин её не добавляет; исправление API-галереи
остаётся отдельной задачей. В Classic Editor ошибок JavaScript в сценарии нет.

## Компоненты Valyro Manacost (1.2)

Рядом с «Вставить статью» доступна кнопка «Компонент Manacost»:
примечание (информация / важно / совет), спойлер, цитата с подписью,
2–6 вкладок и таблица (2–6 столбцов, 1–12 строк данных). Ширина и отступы
настраиваются отдельно. При уменьшении таблицы скрытые ячейки сохраняются
в текущей форме. Отмена сохраняет ввод до перезагрузки; успешная вставка
очищает форму. Пустые тексты, названия вкладок и заголовки таблицы не вставляются.

В Classic Editor кнопка находится над текстом. В Gutenberg — в области
метабокса карточек во вкладке настроек записи Post/«Запись»; при выборе блока
WordPress переключает настройки на Block/«Блок». В Gutenberg вставка создаёт статический блок `hs-manacost/component` с живым
предпросмотром прямо в тексте. Кнопка «Настроить компонент» повторно открывает
форму и обновляет выбранный блок, сохраняя его положение. Вставка доступна также
через стандартный inserter блоков. В Classic Editor компонент отображается в Visual;
текст можно править на месте. Для настройки выберите компонент курсором и нажмите
«Компонент Manacost»: форма загрузит его данные и заменит выбранный блок одной
операцией Undo. В режиме Code кнопка вставляет новый HTML в позицию курсора.

Источники получены установленным `/home/debian/.local/bin/valyro` версии
0.1.0: `manacost-theme`, `alert`, `accordion`, `pull-quote`, `tabs`, `data-table`.
Тема и цитата доступны через существующую Pro-авторизацию CLI. Токены светлой
темы с исходным SHA-256 находятся в `manacost-tokens.css`; их область ограничена
`.hs-article-component`. Реализация — HTML-адаптеры для WordPress, не React-компоненты:
на frontend нет React, ThemeProvider, внешних шрифтов, запросов к Valyro,
токенов доступа, сторонних cookies или нового хранилища данных.
Не переносить коммерческие исходники из приватного репозитория в публичный пакет.

Данные формы записываются через `textContent`, пользовательский HTML не выполняется.
Сохранение/права/KSES/autosave/revisions остаются штатными WordPress. Отдельных
AJAX/REST endpoints и изменений БД нет. Вкладки сохраняются как видимые разделы
с заголовками; небольшой frontend-скрипт добавляет кнопки, ARIA-связи и навигацию
стрелками/Home/End. Без JS и при печати видны все разделы. Спойлер использует
нативный `details/summary`. Таблица прокручивается внутри блока на узком экране.
Стили наследуют шрифт статьи и не переключают тему всего сайта.

Проверки расширяют `tests/article-cards/components.mjs`, основной browser test,
проверку сохранённого контента и staging probe. Staging использует только свой
временный черновик и удаляет его после проверки. При откате на 1.1 текст и
семантическая разметка сохраняются, вкладки становятся обычными разделами.

## Автор и стопка карточек

«Компонент Manacost → Об авторе · соцсеть» вставляет карточку AuthorBio:
имя, подпись, описание, необязательное фото и кнопку с обычной ссылкой HTTP(S).
Кнопка открывает соцсеть в новой вкладке; она не имитирует подписку внутри сайта.
Компонент повторно редактируется тем же способом, что цитата и таблица.

В подборке статей появился вид «Стопка карточек · Folded». От двух карточек
доступны стрелки, клавиши ←/→/Home/End и горизонтальный свайп; автоперелистывания
нет. При отключённом JavaScript или печати видны все ссылки. Системное уменьшение
движения отключает трансформации/переходы. В редакторе доступен живой предпросмотр
в окне вставки; сохранённое содержимое остаётся обычным HTML.

Автоматические превью обычных ссылок удалены в версии 1.4: ссылки сохраняют
нативный переход, без всплывающих карточек, дополнительных кнопок и запросов
метаданных. Endpoint `hs-article-cards/v1/preview` удалён. Содержимое старых
статей не меняется; игровые подсказки HS Tooltip остаются самостоятельными.

Канонический исходник плагина — Manacost. На Koloda используется идентичный пакет
через `config/shared-plugin-lock.json`: каталог Koloda локальный, Manacost внешний.
Базы, настройки, лицензии, медиа и плагины темы/кэша между сайтами не переносятся.
Откат версии проходит через штатный release pipeline; опубликованный HTML остаётся
читаемым, автоматические превью отключаются вместе с кодом.

### Inline images and mobile tabs

Classic Editor exposes **Картинка в строке** beside the media button. Place the
caret in a paragraph and choose an image from the native media library. Gutenberg
exposes the same action in the text formatting menu. Alt text comes from the
selected attachment. The saved image is ordinary inline HTML with a `1em` height,
so it follows the text size, supports undo/autosave/revisions, and remains inline
when the plugin is disabled. The source image is never resized or overwritten.
On screens below 600px tabs use one horizontally scrollable row with 44px touch
targets; keyboard navigation and all panels remain available.

For isolated Koloda fixtures, set `HS_ARTICLE_CARDS_LOCAL_SOURCE` to `koloda`;
production identifies its local catalog from the canonical home host.
`HS_ARTICLE_CARDS_REMOTE_ENABLED=false` disables both remote providers without
affecting local search or saved cards. The legacy Koloda-only switch still works.

Reopening tabs preserves inserted images, their native media classes/dimensions,
and unchanged body markup. Rich bodies remain editable in the main article editor;
the text-only dialog does not flatten them. On mobile, Shortcodes Ultimate boxes
containing these tabs collapse direct empty spacer paragraphs at render time;
the stored article and desktop spacing are unchanged.

### Оформление статьи (1.4)

В меню «Компонент Manacost» доступны четыре дополнительных элемента:

- Разделитель: тонкая линия, пунктир или ромб; подпись можно оставить пустой.
- Список с иконками: галочка, звезда или стрелка; каждый пункт с новой строки.
- Шаги: нумерованная последовательность от 1 до 20 пунктов.
- Акцентный блок с кнопкой: заголовок, текст, цвет акцента и ссылка HTTP(S),
  которую можно открывать в текущей или новой вкладке.

Для каждого доступны ширина, обычные/компактные отступы, живой предпросмотр и
повторное редактирование через ту же кнопку. В Classic Editor выберите элемент
в тексте, в Gutenberg нажмите «Настроить компонент». Сохраняется обычный HTML:
списки и ссылки работают без JavaScript, автосохранение и revisions остаются
нативными. Оглавление не добавляется. Новые библиотеки и внешние запросы не нужны.
