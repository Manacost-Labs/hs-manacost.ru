# MCP для статей Manacost

Сервис даёт ИИ-клиенту поиск и полный текст опубликованных статей
`hs-manacost.ru`. WordPress остаётся источником данных, а SQLite FTS5 хранит
отдельный поисковый индекс. MCP читает материалы; инструментов редактирования,
публикации, управления пользователями и загрузки изображений нет.

## Текущий статус

Проверка опубликованных статей выполнена **1 октября 2026 года** на версии
`065acc0a7f96cec0d488bd132a64ee11a230b344`; новый OAuth-модуль проверяется отдельно:

| Способ подключения | Статус |
|---|---|
| STDIO — клиент запускает локальный процесс | Работает. Проверены запуск CLI, обнаружение четырёх инструментов и все четыре операции на опубликованной статье основного сайта. |
| Streamable HTTP + OAuth — код сервера | Реализован OAuth Manacost через существующий вход Hearthpulse. Официальный SDK проходит discovery, DCR, PKCE, получение JWT и чтение статьи. |
| Публичный `https://hs-manacost.ru/mcp` | **Ещё не включён: HTTP 404.** OAuth Manacost выключен по умолчанию; отдельное staging/production развёртывание ещё требуется. |

Базовые 12 автоматических тестов прошли; новый OAuth имеет дополнительные regression и браузерные проверки. [Свежая проверка staging](https://github.com/Manacost-Labs/hs-manacost.ru/actions/runs/36836346777)
проиндексировала 20 статей и проверила поиск, рубрики и пять чтений полного текста.
Эта проверка использует MCP внутри процесса и настоящий REST API staging;
она не проверяет вход пользователя через публичный OAuth.

Для удалённого HTTP-доступа предусмотрены **действующие администраторы
Hearthpulse**, включая пользователей с входом через Telegram. Роль и блокировка
аккаунта проверяются при каждом запросе. STDIO использует права локального
пользователя, запускающего процесс, и не выполняет вход через Hearthpulse.

## Инструменты

| Инструмент | Аргументы | Результат |
|---|---|---|
| `search` | `{"query":"маг элементал"}` | До 20 совпадений: ID, заголовок и URL для ссылки на источник. |
| `fetch` | `{"id":"12345"}` — ID из поиска или списка | Полный Markdown, URL, дата изменения и ID рубрик. |
| `list_articles` | `{"cursor":"0","limit":20}` | Страница архива и `next_cursor`. Продолжать до `null`, в том числе после пустой отфильтрованной страницы. |
| `list_categories` | `{"page":1}` | Рубрики и `next_page`; продолжать до `null`. |

ID в `fetch` передаётся строкой. Поиск сопоставляет начала слов, включая
кириллицу, и требует совпадения всех слов запроса. Это полнотекстовый поиск;
семантические embeddings и морфологический разбор не используются.

В индекс входят опубликованные записи без пароля. Черновики, закрытые материалы,
ревизии и персональные данные пользователей не запрашиваются. Перед выдачей
текста сервис сверяет публикацию, пароль и дату изменения с WordPress. Изменённая
статья недоступна до синхронизации; при отказе источника возвращается ошибка.
Изображения передаются ссылками, включая S3, и не скачиваются на диск.

Основной источник — `hs-manacost.ru`. Для проверок разрешён отдельный
`test.hs-manacost.ru`; его индекс нельзя смешивать с production. Зеркало `.com`
не является вторым архивом. `kolodahearthstone.com` сейчас не подключён.

## Быстрый запуск через STDIO

Требуется Node.js **22.22.2 или новее в ветке 22** (`>=22.22.2 <23`), npm и `flock`.
Используйте checkout всего приватного репозитория: CLI также импортирует
проверку прав из `services/reader/community-clients.js`.

Команды для сервера проекта:

```sh
cd /srv/projects/wordpress/hs-manacost.ru
npm ci --prefix services/articles-mcp --ignore-scripts

# Создать частный каталог вне Git и web root под текущим пользователем.
install -d -m 700 "$HOME/.local/share/manacost-articles-mcp"
export MCP_SOURCE_ORIGIN=https://hs-manacost.ru
export MCP_DATABASE="$HOME/.local/share/manacost-articles-mcp/articles.sqlite"

# Первый sync заполняет индекс опубликованных статей.
flock "$HOME/.local/share/manacost-articles-mcp/sync.lock" \
  node services/articles-mcp/cli.js sync

node services/articles-mcp/cli.js stdio
```

После запуска `stdio` процесс ждёт протокол MCP на stdin. Обычно его запускает
сам ИИ-клиент. Индекс должен быть заполнен до подключения: сервер не запускает
синхронизацию автоматически.

Пример для клиента с форматом `mcpServers`:

```json
{
  "mcpServers": {
    "manacost-articles": {
      "command": "node",
      "args": [
        "/absolute/path/to/hs-manacost.ru/services/articles-mcp/cli.js",
        "stdio"
      ],
      "env": {
        "MCP_SOURCE_ORIGIN": "https://hs-manacost.ru",
        "MCP_DATABASE": "/absolute/path/to/private/articles.sqlite"
      }
    }
  }
}
```

Замените оба пути на пути **машины, где клиент запускает процесс**. Там должны
находиться checkout, установленные зависимости, Node.js и заполненный индекс.
Формат настроек зависит от клиента. Облачному клиенту, принимающему только URL,
потребуется удалённый HTTP-сервис после его активации.

Обычный `sync` добавляет и обновляет статьи и удаляет из индекса снятые материалы.
`sync --full` перечитывает все тексты, в том числе изменённые фильтрами и
шорткодами без изменения даты статьи. Рекомендуемый график — обычный sync каждые
пять минут и полный вне пика нагрузки. Используйте один worker с `flock`;
не направляйте его вывод в канал STDIO клиента.

## Удалённый HTTP и Hearthpulse

Предполагаемый адрес подключения — `https://hs-manacost.ru/mcp`.
**Этот адрес пока не готов для добавления в ИИ-клиент.** На дату проверки и он,
и `/.well-known/oauth-protected-resource/mcp` возвращают 404.

OAuth реализован здесь, в `services/reader/mcp-oauth*.js`. Клиент регистрируется
у Manacost, пользователь входит через существующий Hearthpulse/Telegram и явно
подтверждает доступ. Новый OAuth-модуль выпускает собственный JWT для MCP;
Hearthpulse остаётся источником текущих прав администратора.
[Настройка, endpoint-контракт, ключи, выпуск и rollback](../../docs/runbooks/mcp-oauth.md).

Сервер ожидает подписанный JWT access token с `typ=at+jwt`, алгоритмом RS256,
issuer `https://hs-manacost.ru/mcp-oauth`, audience `https://hs-manacost.ru/mcp`
и scope `articles:read`. Максимальный возраст токена — 15 минут.
ID token и непрозрачный access token не принимаются. После проверки токена сервер обращается к
каноническому API прав Hearthpulse. Снятие роли, блокировка или отказ API прав
закрывают следующий запрос.

Для запуска режима `http` используются те же `MCP_SOURCE_ORIGIN` и
`MCP_DATABASE`, а также:

| Переменная | Значение |
|---|---|
| `MCP_RESOURCE_URL` | Точный HTTPS URL ресурса с путём `/mcp`. |
| `MCP_OAUTH_ISSUER` | `https://hs-manacost.ru/mcp-oauth`. |
| `MCP_OAUTH_JWKS_URL` | `https://hs-manacost.ru/mcp-oauth/jwks`. |
| `MCP_PERMISSIONS_CLIENT_SECRET` | Секрет существующего Reader permissions client для соответствующего окружения; только из защищённого хранилища. |
| `MCP_PORT` | Необязательный loopback-порт; по умолчанию `8792`. |

Запуск: `node services/articles-mcp/cli.js http`. Процесс слушает только
`127.0.0.1`; внешний HTTPS reverse proxy, OAuth-регистрация клиентов, изолированная
проверка staging и постоянная синхронизация требуют отдельной настройки.
Шаблоны reverse proxy/systemd находятся в `ops/articles-mcp`.
Обычный deployment WordPress не устанавливает и не запускает этот сервис.
Подробные условия выпуска: [runbook](../../docs/runbooks/articles-mcp.md#remote-http-and-oauth).

## Проверка и диагностика

```sh
# Из корня репозитория: locked install, audit, syntax и 12 тестов.
make articles-mcp-test

# Защищённая read-only проверка настоящих статей staging в GitHub Actions.
gh workflow run articles-mcp.yml --ref main
```

Workflow использует существующий серверный runner и защищённые staging secrets,
читает не более 20 статей и выводит только счётчики, размеры и время запросов.
Cookies и тексты статей в отчёт не сохраняются. Для постоянного staging-сервиса
нужно отдельно настроить источник; [стендовый сценарий](../../docs/runbooks/articles-mcp.md#localstdio-setup)
использует временную браузерную сессию.

| Симптом | Что проверить |
|---|---|
| HTTP 404 на `/mcp` | Внешний маршрут и отдельный процесс ещё не развёрнуты. |
| HTTP 401 | Токен, issuer/audience/scope, срок действия, текущие права и доступность Hearthpulse. |
| HTTP 429 | Лимит запросов; повторить после `Retry-After`. |
| Пустой список | Сначала выполнить sync; проверить, что клиент использует тот же абсолютный путь к индексу. |
| `Article unavailable, changed, or source temporarily unavailable` | Проверить источник и синхронизацию. Снятые и защищённые паролем статьи не выдаются. |
| Процесс завершается при старте | Проверить Node.js, зависимости, права на каталог, абсолютный путь к БД и переменные выбранного режима. |

Эксплуатационный контракт, ограничения запросов, выпуск и rollback:
[docs/runbooks/articles-mcp.md](../../docs/runbooks/articles-mcp.md).
