# Functional parity contract

Functional parity means every viewport exposes the same meaningful content, actions, identity, SEO semantics, ads, analytics, and view-count behavior. Geometry may adapt; capability may not silently disappear.

Inventory each surface before editing: header/navigation/search, article metadata and body, media, deck codes, tables, related content, comments, share controls, ads, embeds, consent, errors, loading, empty states, and authenticated controls. Record intentional differences and their user benefit.

Hard failures include content removal, hover-only access, desktop-only controls, duplicated headings, reordered DOM that breaks reading order, a user-agent branch without an explicit cache key, or a viewport meta tag that prevents 200% zoom.

Domain parity is also required. `hs-manacost.ru` remains canonical; `hs-manacost.com` is a working noindex mirror; `test.hs-manacost.ru` is fully noindex. Mirror and staging rules must not change the reader experience accidentally.
